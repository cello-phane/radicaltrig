RKT Math Library — Reference

Plots are the function, approx, and error (on the same axes)

1 RAU = π/2 radians. Each approximation below follows the same pattern: reduce the input to a small fixed interval, fit a Remez minimax polynomial on that interval only, then reconstruct exactly using integer/bit arithmetic. Solid lines are reference values, dotted lines are the polynomial, and the red trace (right axis) is absolute error.

Reading the error axis: the right-hand axis is log-scaled and plotted in plain scientific notation (e.g. 3.7e-8). For a quick intuitive read, that maps to SI magnitude prefixes — µ = 10⁻⁶ (micro), n = 10⁻⁹ (nano), p = 10⁻¹² (pico). So 3.7e-8 ≈ 37 n, 1.68e-7 ≈ 168 n, and 7.1e-4 ≈ 710 µ. Smaller prefix order (p < n < µ) means a tighter fit — float32-class functions in this library sit in the tens-to-hundreds of n range, while float16-class functions sit in the hundreds of µ range.

§1 — warp(t): the diagonal-to-arc correction

5.6e-7 · float32

Maps the raw diagonal parameter t ∈ [0,1] to the arc-uniform coordinate w = sin(t·π/2) / (sin(t·π/2) + cos(t·π/2)). Every sin/cos call in the library is this polynomial plus one sqrt.

§2 — rau_sincosf vs cs_poly_sincos

1.68e-7 / 1.77e-7

Two independent pipelines for sin/cos. rau_sincosf warps then normalises via one sqrt; cs_poly_sincos fits cos/sin directly with no sqrt at all. Both float32-class.

§3 — erf_poly

3.7e-8 · float32

Degree-10 odd Remez polynomial. EC[0] = 2/√π is recovered independently by the fit. Valid only on [−1.2, 1.2] — diverges outside this domain.

§4 — erfinv_hybrid

≤ 3.8e-7 · float64

Hybrid inverse error function combining two approximation strategies. For |x| ≤ 0.850, RKT uses an original degree-11 minimax polynomial generated with the Remez algorithm followed by one Newton refinement, achieving a verified worst-case error below 3.8×10−7. Beyond this seam, the implementation switches to a three-region double-precision approximation adapted from Mike Giles, Approximating the erfinv Function (GPU Computing Gems Jade Edition, 2010), whose error is near machine precision (~10−15). The crossover at |x| = 0.850 was chosen empirically to maximize performance while maintaining a continuous, low-error approximation across the entire domain.

§4b — erfinv_hybrid (float32 tail)

≤ 3.8e-7 · float32 optimized

Performance-oriented variant using the same RKT minimax polynomial and Newton refinement for |x| ≤ 0.850. For larger magnitudes, the double-precision Giles tail is replaced with the original single-precision two-region formulation (degree 8/8), reducing the number of polynomial coefficients and branches while remaining well within float32 precision requirements. The full hybrid maintains a verified worst-case error below 3.8×10−7, while offering improved throughput on SIMD processors and GPU-oriented workloads where full double-precision tail accuracy is unnecessary.

§5 — exp_poly

3.9e-7 · float32

eˣ = 2ⁿ · P(f), with n = ⌊x/ln2⌋ applied exactly via the IEEE-754 exponent field, and P a degree-5 Remez fit on f ∈ [0,1) only.

§6 — ln_opt: corrected vs buggy coefficients

bug fixed this session

LO2, LO3, LO4 were transcription errors in earlier source — off by ~5e-5 in the 6th–7th significant digit. Inflated true error 4.3× (1.24e-5 → 5.34e-5) while staying under the loose float16 pass threshold the whole time.

§7 — arctan tiers: f16 / hsp / precise

7.32e-7 RAU · join gap 9.74e-11 (precise)

Each tier is independently Remez-fit at its target precision — truncating the precise coefficients to a lower bit width would give a worse result than refitting from scratch. The old (pre-Remez) set is ~180× worse than the new precise tier despite using a similar number of terms. The precise and hsp coefficients are endpoint-constrained so that sum(c) = π/4 exactly, closing the join-point discontinuity at x=1 from 5.70e-7 to 9.74e-11 — the cardinal point on the unit circle diagonal is now exact to double precision.
