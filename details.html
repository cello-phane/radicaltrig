Radical Angle Unit
Forward & Inverse Reference

Complete verified pipeline — Desmos · C · GLSL · Python

§1The One Primitive

Everything in the RAU system is a specialization of a single operation: projecting a point on the unit-square diagonal onto the unit circle. The parameter w measures how far along that diagonal you are. The projection gives (cos, sin) as pure ratios — no transcendental evaluation needed.

w = 0.5 + v·P(v²) ← warp, v = t−½
D = (1−w)² + w² ← always in [½,1]
cos(φ) = (1−w) / √D ← x component
sin(φ) = w / √D ← y component

§2Four Quadrants — the Full Period

The period is 4 RAU = 360°. One unit per quadrant. Integer boundaries land exactly on the four cardinal points. Odd quadrants Q1 and Q3 reverse the warp direction — w → 1−w — which is both the forward rule and the inverse rule.

§3Variable to uniform/constant

dθ/dt = 1 / D(t) ← D(t) = 2t² − 2t + 1
dθ/dt : 1 → 2 → 1 ← as t: 0 → 0.5 → 1
dθ/dt — slow·fast·slow Angle swept per unit of raw parameter. Slowest right at the cardinal endpoints (rate = 1), fastest at the diagonal midpoint (rate = 2, exactly double). This is the free ease-in–out the warp buys: easing out of 0°/90° and back in, with no explicit smoothstep or cosine call.
dt/dθ = D(t) — fast·slow·fast The reciprocal view: raw parameter needed per unit of true angle. Largest at the endpoints (D=1), smallest at the midpoint (D=0.5). Same curve, opposite framing.

Endpoints (t=0,1) and the quadrant midpoint (t=0.5) always land exactly on the true angle regardless of warp — both curves cross there. The warp polynomial (§1) exists purely to flatten dθ/dt to a constant 1 everywhere in between; dropping it keeps the natural bulge instead, which is either a timing error or a free easing curve depending on what the caller actually needs from t.

§4Forward Path φ → (cos, sin)

Three equivalent implementations, all verified to machine precision against each other.

R_vec — the vector cardinal method

Select a cardinal direction vector i from the integer part of φ, then apply the warp and projection within that quadrant. No branching on signs — the cardinal vector carries the sign information.

z = floor(mod(φ, 4))
i = {z<1:(1,0) z<2:(0,1) z<3:(−1,0) z<4:(0,−1)}
w = warp(frac(mod(φ, 4))) ← w in [0,1)
D = 1 − 2w + 2w² ← = (1-w)²+w²

R_vec = (i.x·(1−w) − i.y·w, i.y·(1−w) + i.x·w) ← before normalization
cos = R_vec.x / √D
sin = R_vec.y / √D ← verified: max err ~4.3⁻⁹

§5Normalize with 1/√D

Both R_vec components share the same scalar divisor. Rather than call hardware sqrt+div, 1/√D is approximated directly with a centered polynomial plus one Newton refinement — the same pattern as the warp and arctan fits, applied to reciprocal square root.

(1/√D) = P(D) by the following: d = D − 0.75 ← recenter, d ∈ [−0.25, 0.25]
P_base(d) ≈ 1/√D ← 8-term Estrin fit, see §10
P(D) = ½·(P_base(d)² + 1/D) / P_base(d) ← one Newton-Raphson step
why recenter Fitting 1/√x directly on [0.5,1] produces coefficients spanning a ~208:1 ratio, which amplifies rounding error at float32. Recentering on d = D−0.75 (so d ∈ [−0.25,0.25]) brings the coefficient magnitudes in line and removes that error-amplification path. The Newton step afterward roughly doubles the fit's effective precision for one extra multiply-add.

§6Inverse Path (cos, sin) → φ

Given a circle point R = (cos, sin), recover the original parameter φ. Four methods in increasing precision, all using only the sign bits for quadrant detection.

The odd-quadrant reversal — same rule as forward

Q0, Q2 (even): φ = Q + t ← t counts forward
Q1, Q3 (odd): φ = Q + (1−t) ← t reversed, mirrors forward w→1-w

§7Single-Component Recovery

When only sin or only cos is available — one PMOD pin, one ADC channel, one encoder output — w can be recovered algebraically without the other component.

from sin only r_arcsin = |sin² − √(sin²(1−sin²))| / |2sin²−1| Recovers w. Singularity at sin=1/√2 (w=0.5) — use midpoint guard.
exact
from cos only r_arccos = |cos²−1+√(cos²(1−cos²))| / |2cos²−1| Recovers w. Same singularity at cos=1/√2.
exact
real-time strategy — 2-bit sign register Store sign(cos) and sign(sin) as two bits. Update only at zero crossings (infrequent). Between crossings, interpolate w from the single measured component using r_arcsin or r_arccos. No atan2 call at any point in the steady-state loop.
